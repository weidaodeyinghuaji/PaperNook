# PaperNook × Codex Meter 融合方案

> 状态：路线 C 的 P0 / Phase 1、R1 额度可靠性与 R2 本地发布防呆已完成；Phase 2 分析首批能力与 Phase 3 组件/网络只读能力已完成，剩余安全操作与正式发布门禁继续迭代  
> 日期：2026-09-21  
> 目标版本：PaperNook `V1.1.0-beta.1` 起分阶段交付  
> 产品名称：纸隅 PaperNook

## 1. 当前结论

推荐采用“**原生能力迁移 + PaperNook 纸片化 UI**”，不把 `CodexMeter.exe` 整体塞进 PaperNook，也不把现有 WinForms 窗口套壳嵌入。

最终形态是一张内置的“Codex 状态纸片”：

- 平时像普通 PaperNook 纸片一样驻留桌面；
- 收起后在边缘胶囊显示活动状态与关键额度；
- 悬停 Mini 展示 5 小时、7 天额度、当前任务和本周期成本；
- 展开后通过“概览 / 项目 / 组件 / 网络”四个内部页面查看完整信息；
- 使用 PaperNook 的主题、圆角、纸张色、字体、动画、备份和存储体系；
- 不再启动第二个托盘、第二套桌面窗口、第二套开机启动或第二套更新程序。

Codex Meter 的统计算法和行为规则迁移到 .NET 10/C#，由 PaperNook 统一管理生命周期。Codex CLI `app-server` 仍可作为按需子进程使用，但最终方案不再要求常驻 Node.js、本地 HTTP 端口或独立 WinForms 外壳。

## 3. 三种实现路线

### 路线 A：直接捆绑 CodexMeter-portable

做法：PaperNook 启动 `CodexMeter.exe`，只增加入口或窗口跳转。

优点：最快，几乎不改 Codex Meter。

问题：仍有两个进程体系、两个托盘、两个更新器、两个数据目录和两套 UI；不能称为真正融合，安装包还会显著膨胀。此路线不作为正式方案。

### 路线 B：复用 Node 服务，重做 PaperNook UI

做法：移除 Codex Meter 的 WinForms 外壳，PaperNook 管理其 Node 服务，使用 WPF Body/Mini 展示数据。

优点：能较快复用现有统计代码和 27 个测试；第一版交付速度较快。

问题：仍需随包携带 Node 运行时和服务器文件；存在 localhost API、端口、子进程回收、双缓存和安全边界；PaperNook 当前单文件发布也会变复杂。

定位：只适合作为短期验证分支，不作为最终架构。

### 路线 C：迁移核心算法到 C#，使用内置 Paper Provider

做法：把 JSONL 增量扫描、额度窗口识别、账号隔离、成本估算、组件扫描和网络诊断逐步迁移为 .NET 服务；用 PaperNook 原生 WPF 构建 Body、胶囊和 Mini。

优点：一个产品、一个生命周期、一个托盘、一套主题、一套备份与发布；无需本地 HTTP 端口和 Node 常驻进程；最符合 PaperNook 的长期架构。

代价：迁移工作量最大，必须用原有 Node 测试与脱敏 fixtures 做行为对照。

**推荐路线：C。** 路线 B 仅在需要尽快验证交互时作为可删除的过渡实验，不进入正式 Release。

## 4. 推荐产品形态

### 4.1 普通纸片

新增内置 provider：`builtin.codex-meter`，初始推荐尺寸约 `360 × 430 DIP`。

默认只展示真正需要常驻桌面的信息：

1. 当前账号脱敏标识；
2. Codex 当前状态与并行任务数；
3. 5 小时额度和重置倒计时；
4. 7 天额度和重置倒计时；
5. 当前周期 Token 与 API 等价成本；
6. 手动刷新和“查看详情”。

避免把完整 Dashboard 的所有卡片压进小纸片。趋势、会话、组件与网络信息通过详情页渐进展开。

### 4.2 胶囊

宿主继续拥有胶囊外壳、拖拽、关闭、DPI、队列和输入。Codex Meter 只提交标准 presentation：

- 状态点：空闲、思考、执行工具、生成回答、异常；
- 文本：`5h 49%` 或当前活动；
- 进度条/环：5 小时剩余额度；
- plain-text fallback：额度缺失或服务不可用时仍有可读状态。

### 4.3 Edge Mini

推荐 `360 × 240 DIP`，最多展示：

- 5 小时 / 7 天双进度；
- 当前活动与并行任务数；
- 本周期 Token / 成本；
- 刷新按钮。

Mini 不承载搜索、会话删除、市场浏览等复杂交互，也不依赖键盘焦点。

### 4.4 展开详情

仍在 PaperNook Paper shell 内呈现，使用四个轻量页面：

- **概览**：Token 结构、额度、周期成本、趋势和热力图；
- **项目**：项目与会话统计、搜索、展开、导出和恢复会话；
- **组件**：本机 Skill、Plugin、MCP 清单；
- **网络**：ChatGPT/API 连通性、延迟与检测历史。

Skill 在线市场和第三方风险评分不放在首版主导航，避免把便签扩张成应用商店或网络风控工具。

## 5. 功能分级

### P0：首个可用融合版

- 当前账号脱敏信息；
- 5 小时 / 7 天官方额度窗口，严格按 `300` / `10080` 分钟识别；
- 额度可信缓存和同窗口回退，禁止窗口串位；
- Token 增量统计与项目 Top 列表；
- Codex 本机活动和并行任务状态；
- 当前周期 API 等价成本；
- 纸片、胶囊、Edge Mini、主题和手动刷新；
- 启用/禁用、刷新间隔、数据来源说明和错误降级。

### P1：分析能力

- 今日、7 天、30 天、90 天、自定义范围；
- 输入、缓存、输出、推理 Token 明细；
- 活动热力图和每日趋势；
- USD/CNY 与 ECB 汇率缓存；
- 当前账号 / 本机全部账号切换；
- 7 天额度周期历史与周价值估算；
- JSON/CSV 导出。

### P2：管理与诊断

- 项目和会话明细；
- 恢复 Codex 会话；
- 会话软删除与可视化恢复；
- Skill、Plugin、MCP 清单；
- ChatGPT/API 原生网络诊断；
- 自动检测周期和历史清理。

### 延后或不融合

- Skill 在线市场与自动安装；
- Net.Coffee 第三方风险评分默认展示；
- 会话永久删除；
- 独立托盘、独立桌面 Widget、独立开机启动；
- 独立 localhost Dashboard API；
- 排行榜、成就、社交或云同步。

## 6. 技术结构

建议新增以下内部模块，但在方案确认前不写入当前 Architecture：

```text
src/CodexMeter/
├─ Domain/                    # Snapshot、额度窗口、Token、成本、状态模型
├─ Sources/
│  ├─ CodexSessionScanner    # JSONL 增量扫描
│  ├─ CodexRateLimitReader   # app-server RPC
│  ├─ CodexAccountScope      # 账号哈希与时间段归属
│  ├─ CodexActivityMonitor   # 活动和并行任务
│  ├─ ComponentInventory     # Skill/Plugin/MCP
│  └─ NetworkDiagnostics     # 原生链路检测
├─ Services/
│  ├─ CodexMeterRuntime      # provider 唯一后台 owner
│  ├─ CostEstimator
│  ├─ ExchangeRateReader
│  └─ QuotaHistoryStore
├─ Presentation/
│  ├─ CodexMeterPaperView
│  ├─ CodexMeterMiniView
│  └─ CodexMeterViewModel
└─ Persistence/
   ├─ CodexMeterSettingsStore
   ├─ CodexMeterCacheStore
   └─ CodexMeterTrashStore
```

关键 ownership：

- `CodexMeterRuntime` 每个 provider 只有一个，不允许每张纸启动一套扫描器或 app-server；
- Body/Mini 只是前端 surface，可销毁重建，不承担后台保活；
- PaperNook 宿主继续拥有 PaperWindow、胶囊、Edge Mini 窗口、队列、输入、主题和 DPI；
- 核心 Paper 记录只保存 provider 和几何，不把统计历史塞进 `data.json`；
- Codex Meter 的长期状态与可重建缓存分开保存。

## 7. 数据位置与迁移

建议使用 PaperNook 已有四类目录：

| 数据 | 建议位置 | 说明 |
| --- | --- | --- |
| 设置、额度历史、账号时间段 | `Data\CodexMeter\` | 进入 PaperNook 备份范围 |
| 增量扫描、汇率、网络缓存 | `Cache\CodexMeter\` | 可安全重建和清理 |
| 软删除会话 | `Data\CodexMeter\Trash\` | 不作为普通缓存删除 |
| 导出文件 | 用户选择或 `Notes\CodexMeter\` | 不静默覆盖 |

首次启用时检测 `%USERPROFILE%\.codex-meter`，只提供显式“导入旧 Codex Meter 数据”：

- 可导入额度历史、账号时间段和网络设置；
- 缓存默认不导入，重新扫描；
- `trash` 单独确认后复制；
- 原目录不删除、不移动；
- 不允许 standalone Codex Meter 与 PaperNook 同时写同一份状态文件。

## 8. 安全与隐私

- 不保存 Codex access token、refresh token、完整对话正文或 MCP 环境变量；
- `auth.json` 只读取必要账号标识，在内存中立即哈希，邮箱只做脱敏展示；
- app-server RPC 子进程限时、可取消，并由 PaperNook 生命周期回收；
- 会话恢复只接受经过校验的 session ID 和已知工作目录；
- 会话删除首版不做，P2 必须先完成回收站恢复 UI；
- 网络诊断与 ECB 汇率明确标注外部请求；第三方风险服务默认关闭；
- 最终原生方案不开放 localhost HTTP 服务，减少本机跨进程调用面；
- 导出前明确文件内容和目标位置，不包含认证材料或会话正文。

## 9. UI 统一规则

- 全部颜色从 PaperNook Theme/DynamicResource 获取，不硬编码 Codex Meter 的纯黑、纯蓝或独立暗色体系；
- 沿用 PaperNook 纸张底色、圆角、细描边、弱阴影、紧凑标题栏和现有动画节奏；
- 正文以 `14–16px` 等效字号为基线，关键额度可放大，但不让巨型数字挤压其他内容；
- 先用留白、分组和排版建立层级，再用分隔线，避免完整面板当前较重的“卡片套卡片”；
- 所有图标提供 AutomationName、ToolTip 和键盘入口；
- 进度条同时显示数字，不能只靠颜色；
- 适配浅色、深色、四套配色、高对比度、100%/125%/150% DPI；
- 动画关闭时不依赖过渡完成业务状态切换。

## 10. 分阶段实施

当前进度（2026-09-21）：已完成原生只读引擎、唯一 Runtime、纸片 / 胶囊 / Edge Mini、手动刷新、设置、账号脱敏、300 / 10080 分钟窗口识别、可信缓存、JSONL 增量扫描、成本与项目统计，以及旧 `.codex-meter` 缓存只读导入。随后补齐今天 / 7 天 / 30 天 / 90 天统计、30 天逐日序列、最近 7 天趋势、JSON/CSV 脱敏导出、本机 Skill/Plugin/MCP 清单，以及仅由用户手动触发的 ChatGPT/OpenAI API 网络诊断。独立 C# 行为检查已通过真实本机数据、`app-server` 与网络联调。账号范围切换、汇率、额度周期历史、会话恢复/软删除和发布级多环境门禁仍按 Phase 2–4 推进。

### Phase 0：基线冻结与合同测试（2–3 天）

- 给 Codex Meter 当前本机 `1.14.0` 建立可审查提交，不能覆盖现有未提交成果；
- 脱敏并固化 JSONL、app-server、账号切换、额度回退 fixtures；
- 把 27 个 Node 测试按领域归类，定义 C# 对等输出；
- 确认 MIT / TokenTracker 声明进入 PaperNook `THIRD-PARTY-NOTICES.md`。

### Phase 1：原生只读引擎 + 状态纸片（5–7 天）

- 完成额度、Token、活动、成本的 C# 最小引擎；
- 完成纸片、胶囊、Mini 和降级状态；
- 懒启动：只有存在 Codex Meter Paper 时运行；
- 禁止会话修改和在线市场。

### Phase 2：分析详情（4–6 天）

- 趋势、热力图、项目/会话、账号范围、周期历史、汇率和导出；
- 完成 PaperNook 主题、无障碍和响应式布局。

### Phase 3：组件、网络与安全操作（5–7 天）

- Skill/Plugin/MCP 清单；
- 网络诊断；
- 会话恢复；
- 软删除与恢复 UI。

### Phase 4：迁移、备份和发布门禁（3–5 天）

- 导入旧 `.codex-meter` 数据；
- 纳入 PaperNook 备份恢复；
- 断电、崩溃、缓存损坏、账号切换、无 Codex CLI、断网场景；
- Windows 10/11、100%/125%/150% DPI、多显示器和长时间运行。

预计完整融合为 3–5 周；P0 可先形成 `V1.1.0-beta.1`，后续能力逐级加入。

## 11. 验收门禁

- 5 小时与 7 天窗口在返回顺序变化时仍不串位；
- 旧缓存超时后不伪装成新鲜额度；
- 大量 JSONL 增量扫描不阻塞 UI Dispatcher；
- 同一 provider 只有一个后台 Runtime；
- Paper 折叠、隐藏、Body/Mini 回收后后台生命周期正确；
- 胶囊和 Mini 不破坏现有 Edge authority、拖拽、DPI 和输入规则；
- 不记录 Token、完整对话或环境变量；
- 独立 Codex Meter 数据导入失败时保持原数据不变；
- 备份恢复覆盖非缓存历史和回收站；
- 原 Node fixtures 与新 C# 引擎关键输出一致；
- Release 构建、Persistence、Threading、Plugin API、Lifecycle、CrashRecovery 和 ReleaseSafety 全部通过；
- 真实便携包冷启动、退出、更新与回滚通过。

## 13. 已确认的产品选择

推荐默认方案是：**Codex Meter 成为一张可创建、可收起、可停用的内置“Codex 状态纸片”，而不是 PaperNook 启动即常驻的全局 Dashboard。**

这样既保留 Codex Meter 的核心价值，也不会破坏 PaperNook“桌面上的几张纸”这一产品中心。路线 C 已据此进入实现；后续扩展继续遵守同一产品边界。

## 14. 续篇：从“可以使用”优化到“长期可靠”

当前版本已经能展示额度和本机统计，但真实使用暴露了下一阶段比“继续堆卡片”更重要的问题：数据来源需要更透明，额度 RPC 需要更稳，完整纸片的信息架构需要从长列表升级，手工打包也必须消除版本格式错误。

后续优化遵守四条原则：

1. **先说明数据是否可信，再显示漂亮数字。** 实时 RPC、30 分钟缓存、15 分钟 session 回退和不可用必须是四种明确状态。
2. **只有用户需要时才运行。** 没有 Codex 状态纸片时不扫描、不启动 `app-server`、不做网络诊断。
3. **读取默认安全，修改必须可恢复。** 会话恢复可以做，删除只能先进入回收站，首版不提供永久删除。
4. **完整面板渐进展开。** 小纸片只保留关键状态，分析、项目、组件和网络不能继续无限向下堆叠。

## 15. 优化一：额度读取可靠性与可解释状态

### 15.1 当前问题

当前 `codex app-server` 初始化等待 8 秒、额度读取等待 10 秒。Codex CLI `0.150.1` 对带对象参数的 `account/rateLimits/read` 返回 `-32600`，随后使用无参数请求可以成功；服务偶发较慢时，兼容重试可能超过本轮等待时间。此时 PaperNook 会正确回退到 session 快照，但界面只显示“读取超时”，用户很难判断数字还能不能信。

### 15.2 推荐实现

- 为不同 Codex CLI 版本缓存已成功的 RPC 形态：当前版本优先无参数请求，只有协议错误时才尝试带参数请求；升级 CLI 后重新协商。
- 将启动、初始化、额度请求分开计时并记录内存级诊断，不把认证 token、完整响应或会话正文写入日志。
- 额度请求采用单飞（single-flight）：同一 Runtime 同时最多一项读取，重复点击刷新只合并意图，不并行启动多个 `app-server`。
- 第一轮失败后进行一次短退避重试；连续失败采用带抖动的 `30 秒 → 1 分钟 → 2 分钟 → 5 分钟`，手动刷新可以提前唤醒，但不绕过单飞。
- 评估由 Runtime 持有一个有界 `app-server` lease：空闲 3–5 分钟或最后一张 Codex 纸片消失时关闭；若常驻方案增加的故障面超过冷启动收益，则保留短进程并缓存协议协商结果。
- 将来源显示改为：`实时`、`缓存（N 分钟前）`、`会话回退（N 分钟前）`、`已过期`、`不可用`。回退值仍可信时用黄色信息状态，不用红色错误语气。
- 提供“查看诊断”轻量弹层：Codex CLI 路径与版本、各阶段耗时、最后成功时间、当前回退来源和下一次重试时间；支持复制脱敏摘要。

### 15.3 验收标准

- 当前 Codex CLI 不再先发送已知会失败的请求形态。
- 一分钟内连续点击刷新不会出现多个子进程或覆盖较新的结果。
- RPC 超时后仍显示可信回退及其年龄，过期数据不得继续伪装为当前额度。
- 无 Codex CLI、未登录、断网、服务端 5xx、协议错误和真实超时显示不同的用户提示。
- Runtime Dispose 后不残留 `codex app-server` 子进程。

## 16. 优化二：重新组织完整纸片 UI

完整纸片建议改成宿主内的紧凑分段导航，而不是继续增加纵向卡片：

### 概览

- 账号脱敏标识、活动状态、5 小时/7 天剩余额度；
- 明确写“剩余”，避免用户把 74% 理解成“已使用 74%”；
- 显示来源、采集时间、缓存年龄与重试状态；
- Token、当前周期成本和会话数；
- 最近 7 天微型趋势，保持一屏可读。

### 分析

- 今天、7 天、30 天、90 天、自定义范围；
- 输入、缓存输入、缓存写入、输出与推理 Token 明细；
- 日趋势与活动热力图；
- API 等价成本同时标注“估算，不是订阅账单”；
- USD/CNY 仅在用户启用时读取汇率，显示汇率来源、日期和缓存状态。

### 项目

- 项目搜索、Token/成本/会话数排序；
- 展开后显示会话元数据、模型、开始/更新时间，不读取或展示对话正文；
- 支持导出选定项目的脱敏汇总；
- 路径默认只在 Tooltip 或详情中显示，导出默认不包含完整本机路径。

### 组件

- Skill、Plugin、MCP 分组，显示名称、来源与可用状态；
- 首版只读，不在该页面直接安装在线组件；
- 对重复名称、缺失入口和无效 MCP command 给出本机诊断，但不自动修改配置。

### 网络

- 网络检测必须由用户手动触发；
- 分开显示 DNS/TCP/TLS/HTTP 阶段或至少给出可达性、HTTP 状态和延迟；
- 只检测官方 ChatGPT/OpenAI API 目标，第三方风险评分默认不接入；
- 保存最近少量脱敏检测结果，提供“清除历史”。

Edge Mini 仍保持 360 × 240 DIP，只显示双额度、活动、Token/成本和刷新；胶囊只显示活动状态及 5 小时剩余额度。完整功能不下放到 Mini。

## 17. 优化三：账号、周期和历史数据

### 17.1 账号范围

- 默认仅统计当前账号；提供“当前账号 / 本机全部账号”切换，并明确全部账号数据可能包含历史账号使用量。
- 账号切换继续依赖哈希 key 与时间范围，不持久化原始 account id、JWT 或邮箱全文。
- 切换瞬间先结束旧账号开放时间段，再开始新账号范围；系统时间回拨时使用保守边界，不产生重叠负区间。

### 17.2 额度周期历史

- 以 7 天窗口的 `resetAt` 作为周期身份，不以自然周推测。
- 只有观察到可信 RPC/session 数据时更新周期记录；缺失值不能写成 0%。
- 新周期出现时封存上一周期的 Token、API 等价成本和最后额度观察值。
- 周期历史属于不可重建的用户分析数据，应进入 Data/插件 Runtime state 并随 `.papernook-backup` 备份；扫描索引仍留在 Cache。

### 17.3 汇率和价格表

- 模型价格表带 `effectiveDate` 与来源版本；未知模型显示“未定价”，不能套用相近型号价格。
- CNY 仅作为显示换算，底层成本仍保存 USD；ECB 汇率按日期缓存，离线时注明使用哪一天的汇率。
- 价格表和汇率更新失败不能影响 Token 与额度主功能。

## 18. 优化四：会话恢复与软删除

会话管理是 Phase 3 风险最高的能力，必须按以下顺序实现：

1. **只读会话列表**：先完成搜索、项目过滤、时间和模型元数据。
2. **恢复会话**：调用 Codex CLI 支持的恢复入口；执行前展示目标会话与工作目录，失败不修改任何文件。
3. **软删除**：把选定 JSONL 移入 PaperNook 管理的回收区，同时写入 manifest（原相对位置、长度、SHA-256、删除时间、账号哈希）。
4. **恢复与冲突处理**：目标已存在时绝不覆盖，要求用户选择保留两者或取消。
5. **自动清理**：默认关闭；开启后只清理 manifest 可识别且超过保留期的项目。

首个 V1.1 beta 不提供永久删除，不允许批量操作绕过确认，不修改 `auth.json`、Codex 配置或会话正文。回收区和历史 manifest 属于耐久数据并进入备份。

## 19. 优化五：扫描性能与存储治理

- 继续保留 JSONL byte-offset 增量扫描；增加 `FileSystemWatcher + debounce` 作为快速唤醒，另用低频全量 reconcile 防止漏事件。
- 首次扫描显示文件数、已处理量和取消入口；取消保留上次可信缓存，不发布半份总计。
- 对被截断、替换、并发写入和损坏的 JSONL 分别处理；单文件失败不清空其他会话统计。
- 缓存文档增加 schema、生成版本、账号范围 fingerprint 和源文件指纹；升级失败时丢弃缓存并重建，不迁移为耐久业务数据。
- 设置页显示 Codex Meter 缓存占用并支持独立清理；清理缓存不能删除周期历史、回收站或导出文件。
- 对 2–5 GB 会话数据建立性能基线：冷扫描、增量刷新、峰值内存、UI Dispatcher 最大阻塞时间和退出耗时都进入验收报告。

## 20. 优化六：发布与打包防呆

本轮手工包曾把内部版本写为 `1.1.0-beta1`，而更新安全模块只接受 SemVer `1.1.0-beta.1`，导致程序在创建窗口前拒绝启动。后续必须把这类错误变成发布前自动失败：

- 新增仓库内统一的本地发布脚本，版本、目录名、EXE metadata、ZIP 和哈希均从同一个通过校验的 SemVer 输入产生；正式 Release manifest 仍由签名工作流生成。
- 构建前验证 SemVer；拒绝 `beta1`、空 publisher 占位值、版本与 tag 不一致。
- 每个产物自动执行：图标提取、ProductVersion 检查、隔离便携目录 `--package-smoke-test`、退出码与 crash log 检查、必要文件检查；后续再把 ZIP 解压复验并入正式 Release 工作流。
- 发布包只保留 EXE、便携标记、许可证、说明和必要声明；清理 XML、临时日志和烟雾测试 Data/Cache。
- 未签名构建只能作为本地/预发行测试包，正式更新通道继续要求 Authenticode、SPKI 与 manifest 全部通过。

## 22. 最终完成定义

路线 C 只有同时满足以下条件才算“完整融合”，不能仅以界面已经出现为完成：

- 用户能判断每个额度数字来自哪里、何时采集、是否仍可信；
- 当前账号和全部账号不会串位，7 天周期跨重置仍可追溯；
- 大会话库冷扫描与增量刷新不阻塞纸片交互；
- 组件和网络诊断默认只读、按需、可解释；
- 会话操作全部可恢复，备份覆盖不可重建的历史与回收区；
- 没有 Codex 纸片时不产生后台扫描、网络或子进程成本；
- 便携包在无 .NET 环境可直接运行，图标、版本、退出和 crash log 门禁全部自动验证；
- 代码签名、更新回滚、Windows 10/11、混合 DPI、多屏、真实中断和长期运行门禁通过。

## 23. 2026-09-21 本轮优化实施结果

### R1：额度读取可靠性

- `account/rateLimits/read` 已改为优先发送当前 Codex CLI 支持的无参数请求；仅在 `-32600/-32602` 协议错误时回退对象参数。
- 2026-09-22 修复 app-server 初始化超时根因：.NET `Encoding.UTF8` 会向重定向 stdin 的第一条 JSON 写入 UTF-8 BOM，Codex CLI 不接受该首行；现统一使用 `new UTF8Encoding(false)`，与原 Node 实现保持相同的无 BOM 传输。
- 初始化与额度读取分别使用 12 秒 / 20 秒边界，并记录 CLI 版本、失败阶段、请求形态和分段耗时；错误信息不包含认证 token、会话正文或完整响应。

- UI 已区分实时、缓存、会话回退、混合来源和不可用；混合来源显示最旧观察时间，避免一个实时窗口掩盖另一个旧缓存窗口。
- Codex Meter checks 新增 stdin 无 BOM 契约，并提供显式 `--live-required` 门禁；该门禁必须同时获得 5 小时、7 天窗口和 `codex-rpc` 来源，不能再用“返回了 unavailable 字符串”冒充真实联调成功。

### R2：本地发布防呆

- 新增 `tools/Publish-PaperNook.ps1`；严格接受 `1.1.0-beta.1`，拒绝曾导致启动失败的 `1.1.0-beta1`。

- 新增隔离的 `--package-smoke-test`：使用独立单实例名称与便携数据目录，完成真实初始化后自行退出，不会关闭用户正在运行的 PaperNook。
- 同版本重发改为临时 staging 先验证：ZIP 只包含干净发行文件，现有便携目录只替换 EXE、图标、许可、说明和便携标记，不再递归删除 `Data/Notes/Cache/Backups/storage*.json`。

## 24. 额度链路后续优化方案（2026-09-22）

本次 BOM 修复解决的是确定性传输错误，后续可靠性继续按以下顺序推进：

1. **错误分型**：安全截取 app-server stderr 最后一条结构化错误，只保留错误类别和阶段；区分未登录、CLI 不存在、initialize 超时、额度请求超时、协议错误和子进程提前退出。
2. **协议协商缓存**：以 Codex CLI 路径、文件版本和修改时间组成 fingerprint，记住成功的 `account/rateLimits/read` 参数形态；CLI 更新后自动失效并重新协商。
3. **单次传输重试**：仅对 initialize 传输中断或超时重新启动一次子进程；认证/协议错误不盲目重试，避免放大故障。
4. **诊断详情**：在纸片中增加可复制的脱敏诊断，包含 CLI 版本、阶段耗时、数据来源、最旧观察时间、失败类别与下次重试时间，不包含 token、邮箱全文、会话正文和完整路径。
5. **真实联调门禁**：普通 CI 继续使用脱敏 fake app-server fixture；有登录态的本机发布验证必须运行 `--live-required`，连续三次取得两组窗口后才允许生成 beta 交付包。
6. **缓存恢复门禁**：分别验证实时成功、实时失败使用 30 分钟内缓存、缓存过期后使用 15 分钟内 session、全部过期后明确不可用四种状态，禁止把缺失值写成 `0%`。
