# 纸隅：清单与 AI 日程升级方案

日期：2026-10-02。状态：建议方案，尚未实施；版本为路线建议，不代表已经发布。

## 一、建议的产品方向

把纸隅升级为「桌面执行便签 + 清单计划台 + AI 排程助手」，不直接照搬滴答清单，也不把桌面便签变成复杂管理面板。

清单回答“这件事属于什么”，日期视图回答“什么时候做”，桌面便签回答“现在做什么”，AI 帮助把模糊想法转成可以确认的行动计划。四者共用同一份任务数据，避免任务复制后状态不同步。

用户截图中最值得借鉴的是左侧分类、最近七天按天展开、任务按优先级分组。滴答清单官方把普通清单和智能清单分开，今天、明天和最近七天属于条件筛选，收集箱用于暂时没有归类的任务。[官方清单说明](https://help.ticktick.com/articles/7055782283059396608)

纸隅保留现有纸张质感、贴边胶囊和 Codex 动画；分类结构可以借鉴，图标、品牌、布局细节自行设计。暂不加入团队协作、习惯打卡、复杂甘特图，以免第一阶段失去轻量特点。

## 二、先复用哪些基础

本次检查现有源码：`src/Models.cs` 中的 `PaperItem` 已有稳定 ID、文字、完成状态、排序、关联便签或文件，以及 `ReminderAt`、`ReminderTriggered`。提醒不是从零开发，但当前设置中仍属于实验功能。

`src/McpTools.cs` 已提供读取便签、创建便签、添加或更新任务、设置提醒等入口。已有 Codex 用量模块负责额度和活动显示，不等于应用已经具备 AI 推理能力。

需要新增的重点是清单分类与聚合视图、任务日期语义、重复规则、子任务、计划时间块，以及 AI 草稿确认流程。现有数据、提醒与 MCP 能力应扩展复用，不建立另一套独立任务数据库。

## 三、清单怎么设计

### 1. 可选的「计划台」窗口

从托盘、便签工具栏或快捷键打开；不开计划台时，现有桌面便签照常使用。这是产品范围扩展，但不改变“几张桌面纸”的默认使用方式。

左侧分两层：

- 智能视图：收集箱、今天、明天、最近七天、全部任务；逾期在今天顶部单独分组。
- 我的清单：工作、学习、生活等文件夹，下面放项目或清单；颜色和名称由用户自定义，不预置一堆空分类。

底部放已完成和回收站。自定义筛选后续支持清单、标签、优先级和日期组合；第一版不必提供复杂筛选表达式。

中间默认普通列表，可切换最近七天。右侧是按需打开的详情抽屉，编辑说明、日期、提醒、子任务和关联资料。优先级分组可开关，任务少时不用强行制造四个空分组。

窄窗口使用按天纵向列表，宽窗口使用七天横向列；详情可收起。不强制横向拖动才能看到后几天。

### 2. 桌面便签成为「清单的窗口」

普通待办便签继续有效，新增“钉到桌面”：把某个清单、今天或自定义筛选钉成一张纸。

同一任务在项目清单、今天和桌面纸中只是一份数据的不同展示。任意位置勾选，其他位置同步。智能视图不是任务容器：在今天新增任务应赋予今天的计划日期，并选择归属清单；未选择则进入收集箱。

每张纸可设置显示数量、隐藏完成项、排序和密度。胶囊只展示如“今天 3 项”或下一任务时间，不继续增加长度；Codex 额度和任务摘要可切换，不在同一行塞满。

### 3. 任务的信息层级

默认只露出标题、勾选框和一行必要信息；说明、标签、重复、资料链接放详情内。

新增高、中、低、无四档优先级，子任务、标签、完成时间和回收站恢复。清单颜色表示归属，优先级用独立标识，避免一种颜色承担两种含义。

必须区分三种时间：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| 截止日期/时间 | 最晚什么时候完成 | 周五 17:00 前交报告 |
| 计划开始与结束 | 准备在哪段时间做 | 周三 14:00–15:00 写报告 |
| 提醒时间 | 什么时候通知 | 周三 13:50 提醒 |

只有日期的任务保持“日期”，不能被时区转换成前一天。没有时间安排的任务放待安排区，不强行落到午夜。

## 四、日程怎么升级

滴答清单官方提供多种日历视图，以及任务与日历联动；纸隅第一阶段只做最实用的日程列表与周时间轴。[官方功能页](https://www.ticktick.com/features)

周时间轴支持拖动安排任务、调整时长、显示冲突、锁定固定事件。一个任务可以分成多个时间块，但完成状态仍由同一个任务管理；时间块结束不自动等于任务完成。

必须区分固定事件和可移动任务：会议、就医等固定事件不能被 AI 随意挪动。允许配置工作时间、休息时间、每天最大任务时长、时间块间缓冲。

重复任务明确两种规则：按固定日历周期重复，或完成后隔若干天重复。修改时区分“本次”和“后续”；漏做不生成无限积压。提醒升级需处理休眠恢复、重启后的漏提醒、重复通知和系统通知失败，不能依赖电脑一直开着。

外部日历后续先做 ICS 导入、导出及只读订阅，再评估 Google/Microsoft 授权同步。只读订阅可能存在源站更新延迟，不能宣传为实时双向同步。第一版不承诺与滴答清单双向同步。

## 五、AI 不只是加一个聊天框

滴答清单官方更新记录已经出现 AI 创建任务、拆解项目、整理清单能力。纸隅可以借鉴这些入口，但下面的自动排程是我们建议新增的能力，不是对滴答清单功能的断言。[官方更新记录](https://ticktick.com/public/changelog/en.html)

### 1. 自然语言录入

输入“下周五交报告，提前一天提醒”，解析为任务标题、截止时间和提醒草稿，展示具体日期供确认。常见日期先用本地规则解析，复杂句子才交给 AI。

“周末”“晚上”“找个时间”等模糊表达不得悄悄猜成精确时间；展示推定值与可修改选项。批量粘贴一段文字时，先预览拆出的任务，避免把说明和标题都变成独立任务。

### 2. 项目拆解

对“制作一个视频”生成准备、脚本、录制、剪辑、发布等候选子任务，附带可修改的预计时长和依赖关系。不把 AI 的时长估计当成事实，也不在没有确认时写入几十项任务。

### 3. 今日安排与重新排程

点击“帮我安排今天”，仅读取用户选择的任务、固定事件和时间偏好，生成候选时间块。考虑截止时间、优先级、依赖、可用时段、时长与缓冲；没有足够时间时明确列出未排任务，不硬塞到夜里。

例如：固定会议 10:00–11:00、周五要交报告、今天可用两小时。AI 可以建议 09:00–09:45 收集材料、14:00–15:00 写初稿；不能移动会议，也不能把“建议安排”说成“已经完成”。

用户完成得比预期晚时，提供“只调整剩余任务”的预览。每个变更显示原时间、新时间和原因，支持选中部分应用与一次撤销。已经锁定的时间块保持不动。

### 4. 接入方式

建议两条入口，但顺序实施：先扩展已有 MCP，让用户在 Codex 等支持 MCP 的客户端中读取任务并提出计划；再增加纸隅内置 AI 按钮，通过独立配置的模型服务接入。

这两条入口共用同一个计划草稿和确认机制。MCP 模式依赖外部客户端，并不等于软件内直接聊天；内置模式需要模型服务配置，费用和可用性独立说明。不得读取或复用 Codex 登录令牌来冒充授权，不得把额度剩余显示当成可调用模型的凭证。

AI 输出结构化草稿，本地校验日期、冲突、重复、权限、依赖和任务版本后才能应用。生成过程中用户改了任务，应提示草稿过期，不覆盖最新修改。计划分析不上传所有便签，只上传用户授权的最小内容；凭证存入 Windows 安全凭证机制，不写进便携目录和日志。

断网、模型失败、额度不足时，清单、手动排程和提醒仍可使用。AI 失败只影响建议，不影响核心任务数据。

## 六、视觉和动画

保留纸隅暖纸色与柔和边框，使用清单色小标识；减少卡片套卡片的厚重感。日期、任务数量和优先级层级明确，小字号不能用过低对比度。

完成任务用短促勾选与折叠反馈；拖到日程先展示时间块预览，松手后轻量吸附；AI 建议用半透明虚线时间块，应用后变为实体。动效服务于“草稿/已确认/完成”的区别，不持续闪烁。

现有 Codex 空闲、思考、工具状态动画继续独立；AI 排程请求使用自己的状态源。不能把“Codex 正在思考”误显示成“日程 AI 正在处理”。支持减少动态效果，缩放和高 DPI 下不遮挡百分比、日期及操作按钮。

## 七、技术边界与迁移

沿用 WPF、现有 StateStore 和 PaperCommandService。任务仍保持稳定 ID；智能视图只保存查询配置，不保存任务副本。当前任务嵌在便签内，因此清单归属和计划台聚合需要明确建模，不能简单复制成另一份列表。

第一阶段建议普通待办纸继续作为任务归属容器，新增分类元数据和可查询的视图纸。需要进一步支持任务离开原纸独立存在时，再做明确的任务存储迁移，不暗中切换数据权威。

增加计划日期、截止时间、优先级、标签、父任务关系及完成时间；日程时间块作为引用任务 ID 的独立对象。新增字段使用兼容默认值，已有文字、顺序、关联链接、提醒和完成状态不能丢失。

所有 AI/MCP 写入走统一命令层，批量应用保证原子性，记录可撤销的前后值。迁移前备份并提供失败回滚；老版本读取新数据的行为需要验证，不能未经验证承诺任意降级。

## 八、实施顺序和验收

| 阶段建议 | 实施范围 | 必须验收 |
| --- | --- | --- |
| V1.2 清单基础 | 文件夹/清单、收集箱、今天/明天/最近七天、优先级、搜索、桌面视图纸 | 多视图同一任务同步；无复制任务；旧数据迁移及备份恢复；缩放不遮挡 |
| V1.3 日程闭环 | 计划时间与截止时间分离、周时间轴、时间块、重复、可靠提醒、子任务 | 跨午夜/日期任务/时区；固定事件锁定；休眠和重启后提醒不重复；拖动撤销 |
| V1.4 AI 助手 | MCP 计划草稿、自然语言录入、任务拆解、日程建议；随后接内置模型入口 | 先预览后确认；本地冲突校验；过期草稿拒绝覆盖；批量原子应用与撤销；断网仍可管理任务 |

版本仅是建议；每阶段只更新现有唯一便携目录，保留用户数据，不再次堆积多个可运行旧版本。发布、清理已有版本和 GitHub 写入另按实际授权执行。

建议优先把 V1.2 做完整，再做日程，然后接 AI。最先可交付的闭环是“快速记录 → 收集箱归类 → 今天/最近七天查看 → 钉到桌面 → 完成同步”。不要把尚未完成的清单、提醒和 AI 一起包装成一次已经完成的大升级。
